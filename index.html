How this works

Each character's or vehicle's position is stored twice: once in a table column that the server uses as a cache, and once inside a serialized data block that the game actually reads on load. A truck, trailer, or towing glitch can corrupt that second copy to NaN ("not a number") while leaving the table column untouched, nulled, or zeroed — the server then can't work out which map chunk to stream it into. For a character that means a black screen and an endless loading spinner; for a vehicle it just quietly vanishes, since it can no longer be placed in any chunk.

Vehicles (in vehicles.db) have one extra wrinkle: alongside x/y, there's a wx/wy pair marking which world chunk the vehicle belongs to. A corrupted vehicle typically shows wx=0, wy=0 — the map's origin — rather than NULL. This tool computes wx/wy automatically from whatever coordinates you choose, so you don't need to work that out by hand.

This tool scans every character and vehicle for both flavors of this corruption, lets you pick a known-good location to move affected ones to (including matching a vehicle's spot to a character's, or vice versa), and patches every copy together so they all agree again.
