How this works

Each character's or vehicle's position is stored twice: once in a table column that the server uses as a cache, and once inside a serialized data block that the game actually reads on load. A truck, trailer, or towing glitch can corrupt that second copy to NaN ("not a number") while leaving the table column untouched, nulled, or zeroed — the server then can't work out which map chunk to stream it into. For a character that means a black screen and an endless loading spinner; for a vehicle it just quietly vanishes, since it can no longer be placed in any chunk.

Vehicles (in vehicles.db) have one extra wrinkle: alongside x/y, there's a wx/wy pair marking which world chunk the vehicle belongs to. A corrupted vehicle typically shows wx=0, wy=0 — the map's origin — rather than NULL. This tool computes wx/wy automatically from whatever coordinates you choose, so you don't need to work that out by hand.

Some towing/trailer glitches go further than position — they can also scramble a fixed-size rotation/physics block inside a vehicle's data, and occasionally scatter smaller pockets of the same corruption deeper into its parts or cargo data. A vehicle with this problem can have a perfectly valid position and still refuse to spawn, or a position fix alone can leave it invisible. This tool scans for that too, tagged separately as "physics data corrupted." Where possible it repairs the fixed block by copying it from another healthy vehicle of the exact same model already in the file; anything deeper that can't be matched against a known-good donor gets zeroed out instead of left unreadable.

This tool scans every character and vehicle for all of these corruption types, lets you pick a known-good location to move affected ones to (including matching a vehicle's spot to a character's, or vice versa), and patches every copy together so they all agree again.
